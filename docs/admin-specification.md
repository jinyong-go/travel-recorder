# 관리자 웹 명세 (초안)

본 문서는 관리자 웹(`frontend/admin/`)이 **화면으로 무엇을 보여주고 어떻게 동작하는지**를 정의한다.
서비스 규칙은 [specification.md](./specification.md), 사용자 웹은 [frontend-specification.md](./frontend-specification.md)가
기준이다. 실행 방법은 [README](../frontend/admin/README.md)에 있다.

> **지금은 목업 초안이다.** 백엔드에 관리자 역할과 관리자 API 가 없어(공통 명세 §3.11, §7.3)
> 화면은 앱 안의 고정 목업 데이터로만 동작한다. 실제 데이터와 혼동하지 않도록 모든 화면 상단에
> **"목업 데이터"** 배지를 늘 보인다.

## 1. 원칙

- 사용자 웹과 **따로 빌드·배포하는 별개의 앱**이다. 코드를 공유하지 않는다.
- 관리자 웹도 공개 범위 판정식을 갖지 않는다. 판정은 백엔드만 한다 (공통 명세).
- 조회 전용이다. 사용자·여행·그룹을 바꾸는 동작은 두지 않는다.
- 테마 선택 메뉴를 두지 않고 시스템 설정(라이트·다크)을 따른다.

## 2. 화면

| 경로 | 화면 | 내용 |
|---|---|---|
| `/` | 대시보드 | 최근 14일 로그인 통계 |
| `/users` | 사용자 | 가입한 사용자 목록과 검색 |
| 그 밖 | 없는 페이지 | "페이지를 찾을 수 없어요" 와 대시보드로 가는 링크 |

모든 화면은 왼쪽 메뉴(대시보드·사용자)와 상단 바를 공유한다. 폭이 720px 이하이면 메뉴를 상단 가로줄로 바꾼다.

### 2.1 대시보드

- 공통 명세 §3.11 의 로그인 통계(하루 단위 **로그인 횟수**, **로그인한 사용자 수**)를 보여 준다.
- 요약 두 칸: 기간 전체의 로그인 횟수 합계, 하루 평균 로그인 사용자 수(소수 첫째 자리).
- 막대 차트: 날짜별 로그인 사용자 수. 막대에 마우스를 올리면 날짜·사용자 수·로그인 횟수를 띄운다.
  막대는 보조 표현이라 보조 기술에서는 숨기고, 같은 값을 아래 표가 전한다.
- 표: 최근 날짜부터 날짜·로그인 사용자·로그인 횟수.
- 로그인이 없던 날은 0으로 보인다 (공통 명세 §3.11 "0으로 남긴다").

### 2.2 사용자

- 최근 가입순으로 20명씩 보여 주고 "더 보기"로 이어 붙인다.
- 열: ID · 이름 · 이메일 · 가입일 · 마지막 로그인(없으면 "—").
- 검색창에 이름 또는 이메일 일부를 넣고 검색을 누르면 그 조건으로 처음부터 다시 읽는다.
  결과 수를 목록 위에 "N명" 으로 보인다.
- 결과가 없으면 검색 중일 때 "찾는 사용자가 없어요.", 아닐 때 "가입한 사용자가 없어요." 를 보인다.

### 2.3 공통 상태

- 읽는 중: "불러오는 중…"
- 실패: "…을(를) 불러오지 못했어요." 와 "다시 시도" 링크 버튼.

## 3. 백엔드 연동 전에 정할 것

다음이 정해지기 전까지 목업을 유지한다. 정해지면 공통 명세·백엔드 명세·API 명세에 먼저 반영한다.

- **관리자 역할과 인가** — 누가 관리자인지, 어떻게 지정하는지, 관리자 웹의 로그인 방식(네이버 로그인 재사용 여부).
- **관리자 API** — 로그인 통계 조회(기간 지정), 사용자 목록·검색. 응답은 기존 목록 응답(`PageResponse`) 형식을 따른다.
- **이메일 노출** — 관리자 화면에 사용자 이메일을 보일지. 개인정보이므로 범위와 근거가 필요하다.
- **배포 오리진** — dev·prod 의 관리자 웹 주소와 CORS 허용 오리진 추가.
