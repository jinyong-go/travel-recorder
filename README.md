# 여행 지도 (travel-recorder)

다녀온 **여행**을 단위로 방문 장소를 개인 기록으로 남기고, 원하는 상대에게만 선택적으로 공유하는
웹 애플리케이션입니다. 네이버 계정으로 로그인한 사용자가 여행(기간·인원·예산)을 만들고 그 하위에
방문 기록(사진·메모·평점)을 등록합니다. **공개 범위는 여행 단위로 정하며** 기본값은 비공개입니다.
공유 그룹을 만들어 그 멤버에게만 보여주거나 전체 공개할 수 있고, 여행을 공유하면 하위 기록이
전부 함께 보입니다. 목록은 내 것·공유받은 것·둘러보기로 나뉘고, 위치는 네이버 지도로 확인합니다.

## 구성

서비스가 **무엇인지**(도메인 개념과 규칙, 핵심 행위, 공개 범위 정책, 외부 API 제약)는
[공통 요구사항 명세](./SPECIFICATION.md)에 정리되어 있고, **어떻게 만드는지**(엔티티·API·화면)는
각 모듈 명세가 정의합니다.
공개 범위·공유 모델과 여행 계층을 어떤 근거로 정했는지는 [설계 검토 노트](./REFERENCE.md)에
유사 서비스 조사 결과와 함께 있습니다.

## 빠르게 실행하기

두 모듈을 각각 띄웁니다. 백엔드는 8080, 프론트엔드는 5173 포트를 사용하며
백엔드 CORS에 `http://localhost:5173`이 이미 허용되어 있어 별도 프록시 설정이 필요 없습니다.

```bash
# 터미널 1 — 백엔드 (local 프로파일, 인메모리 H2)
cd backend && ./gradlew bootRun

# 터미널 2 — 프론트엔드
cd frontend && npm install && npm run dev
```

네이버 로그인과 장소 검색을 쓰려면 API 키가 필요합니다. 키 없이도 서버는 기동되며
목업 데이터로 화면을 확인할 수 있습니다. 발급·설정 방법은 각 모듈 README를 참고하세요.

## 현재 상태

[설계 검토 노트](./REFERENCE.md)를 거쳐 모델이 두 번 바뀌었습니다.

1. "모두가 공유하는 여행지 + 여러 사용자의 리뷰" → **"개인 소유 방문 기록 + 공개 범위"**
2. 평면적인 방문 기록 목록 → **"여행(Trip) → 여행 기록(TripRecord)" 2계층, 공유의 단위도 여행**
   — 이 개정에서 `VisitRecord` 는 부모와의 관계가 드러나도록 `TripRecord` 로 개명되었습니다
   (API 경로 `/api/records` 와 오류 코드는 그대로입니다).

두 개정 모두 **명세와 백엔드 코드에 반영되어 있습니다.**

- **백엔드**: 여행·여행 기록·공개 범위(여행 단위)·공유 그룹·초대 목록·태그·사진이 구현되어
  있습니다. 공개 범위 판정은 조회 쿼리 단계에서 하며, 기록 조회는 항상 소속 여행을 조인합니다.
  다만 시큐리티 인가 정책이 개발 편의를 위해 `permitAll()`로 열려 있어, 인증이 필요한
  엔드포인트는 컨트롤러가 직접 막고 있습니다.
- **프론트엔드**: 여행 목록·만들기·상세와 기록 등록·상세·수정, 그룹·초대 화면이 구현되어
  있으나 **아직 백엔드 API를 호출하지 않고 목업 데이터를 사용**합니다.
- 스키마 마이그레이션 도구가 없어 `schema.sql` 을 새로 쓰는 방식으로 구조를 바꿨습니다.
  **기존 개발용 데이터베이스는 재생성해야 합니다.**
- 다음 단계는 두 모듈의 API 연동과 시큐리티 재활성화이며, 남은 작업은
  [backend/SPECIFICATION.md §8](./backend/SPECIFICATION.md)과
  [frontend/SPECIFICATION.md §10](./frontend/SPECIFICATION.md)에 정리되어 있습니다.
