# 여행 지도 (travel-recorder) 프론트엔드 요구사항 명세서

## 1. 개요

### 1.1 목적
사용자가 방문한 장소를 **개인 기록**으로 남기고 원하는 상대에게만 선택적으로 공유하는 웹
애플리케이션의 프론트엔드를 구축한다. 사용자는 네이버 계정으로 로그인한 뒤 방문 기록을 등록하고,
각 기록의 공개 범위를 직접 정하며, 내 기록·공유받은 기록·공개된 기록을 나눠 조회한다.

### 1.2 범위
본 문서는 프론트엔드(React + Vite, `frontend/`)의 화면·기능·데이터 요구사항을 정의한다.
서비스 전반의 공통 규칙은 [`../SPECIFICATION.md`](../SPECIFICATION.md) 가 정의하며
**충돌 시 공통 명세가 우선한다.** API 명세는
[`backend/SPECIFICATION.md`](../backend/SPECIFICATION.md) 를 따른다.

### 1.3 용어
[공통 명세 §1.3](../SPECIFICATION.md) 을 따른다. 화면 문구에서는 다음 표기를 사용한다.

| 개념 | 화면 표기 |
|---|---|
| VisitRecord | "기록" (목록 제목은 "내 기록", "공유받은 기록") |
| visibility `PRIVATE` | "나만 보기" |
| visibility `GROUP` | "그룹 공유" |
| visibility `PUBLIC` | "전체 공개" |
| Group | "공유 그룹" |
| rating | "평점" (별점 UI) |

### 1.4 이전 판과의 차이
이 개정판은 [공개 범위 및 공유 설계 검토](../REFERENCE.md)의 결론을 반영한다. 폐기된 화면·기능:

- 여행지 상세의 **리뷰 목록·리뷰 작성 폼·평균 별점·별점 분포** — 기록마다 평점이 하나뿐이라 사라졌다
- 타인의 여행지에 별점·코멘트를 남기는 동선 전체
- 비로그인 사용자의 전체 목록 열람 (이제 `PUBLIC` 기록만)

추가된 화면·기능: 목록 탭(내 기록/공유받은 기록/둘러보기), 공개 범위 선택·변경, 공유 그룹 선택,
그룹 관리 화면, 초대 링크 발급·수락 화면.

## 2. 사용자 및 인증

### 2.1 로그인
- **네이버 로그인(NAVER OAuth 2.0)** 만 지원한다. 자체 회원가입/이메일·비밀번호 로그인은 없다.
- 헤더 우상단에 비로그인 시 "로그인" 링크를, 로그인 시 사용자 프로필(이름·프로필 사진)과
  로그아웃 메뉴를 배치한다.
- 로그인 버튼은 백엔드 `/oauth2/authorization/naver` 로 전체 페이지 이동하며, 실패 사유는
  `?error=` 쿼리로 받아 안내한다.
- 로그인 상태는 새로고침 후에도 유지된다 (세션 쿠키). 세션 만료 시 안내 후 재로그인을 유도한다.
- 모든 API 요청은 `credentials: 'include'` 로 보내고, 쓰기 요청에는 `X-XSRF-TOKEN` 헤더를 붙인다
  (공통 명세 §6.1).

### 2.2 비로그인 사용자가 할 수 있는 것
- **`PUBLIC` 기록만** 목록·상세로 열람할 수 있다 ("둘러보기").
- 장소 검색 모달은 열 수 있으나, 등록으로 이어지려면 로그인이 필요하다.
- 기록 등록, 공개 범위 변경, 그룹 생성·가입, 사진 업로드는 모두 로그인이 필요하며 시도 시
  로그인 화면으로 유도한다.
- 초대 링크(`/invites/:token`)는 비로그인으로 열 수 있고, 어떤 그룹의 초대인지 보여준 뒤
  "로그인하고 참여하기"로 유도한다.

### 2.3 권한에 따른 UI
- **편집 UI(수정·삭제·공개 범위 변경·사진 추가)는 작성자 본인에게만 노출한다.**
  응답의 `isAuthor` 로 판단한다.
- 공개 범위 배지와 공유 그룹 목록은 **작성자에게만** 보인다. 열람자에게는 노출하지 않는다.
- 버튼 노출 제어는 편의 기능일 뿐이며, 실제 차단은 서버가 한다 (공통 명세 §2.2).

## 4. 기록 목록 (`/records`)

### 4.1 헤더 (`app-header`)
- 좌측: 위치 핀 아이콘 + "여행 지도" 타이틀 + "by YONG" 서브 라벨.
- 우측(`header-actions`): 좌측부터
  1. 그룹 관리 진입 (`/groups`) — 로그인 시에만 노출
  2. 설정 메뉴 (`SettingsMenu`) — 지도 표시 방식
  3. 테마 토글 — 라이트/다크 (§6)
  4. 로그인 링크 또는 프로필/로그아웃 메뉴

### 4.2 범위 탭
목록 최상단에 **범위 탭**을 배치한다. 공통 명세 §6.2의 세 범위에 1:1 대응하며,
API의 `scope` 파라미터로 전달된다.

| 탭 | `scope` | 비로그인 |
|---|---|---|
| 내 기록 | `mine` | 숨김 |
| 공유받은 기록 | `shared` | 숨김 |
| 둘러보기 | `public` | **표시 (유일한 탭)** |

- 로그인 사용자의 기본 탭은 **"내 기록"** 이다. 비로그인은 "둘러보기"만 보이며 그것이 기본이다.
- 탭 변경 시 페이지는 1페이지로 초기화된다.
- 빈 상태 문구는 탭마다 다르게 쓴다.
  - 내 기록: "아직 기록이 없습니다. 다녀온 곳을 남겨보세요."
  - 공유받은 기록: "공유받은 기록이 없습니다. 그룹에 참여하면 여기에 표시됩니다."
  - 둘러보기: "공개된 기록이 없습니다."

### 4.3 카테고리 탭 · 정렬
- 카테고리 탭: 전체 / 관광지 / 쇼핑 / 맛집. 선택된 탭은 활성 스타일로 표시된다.
- 목록 툴바: 좌측에 총 건수("총 N건"), 우측에 정렬 셀렉트(최근 등록순 / 평점순 / 거리순).
  **"평점순"은 기록에 매겨진 작성자 본인의 평점 기준**이다 (평균 별점 개념은 없다).
- 범위·카테고리·정렬·페이지는 모두 쿼리 파라미터로 유지한다
  (`?scope=&category=&sort=&page=`). 상세에서 돌아와도 목록 상태가 보존되어야 한다.

### 4.4 기록 카드 (`place-grid` → `record-grid`)
카드 1건은 다음을 포함한다.

- 썸네일 영역: 첫 번째 사진, 없으면 카테고리 아이콘 + 카테고리 배지
- 장소명, 지역명
- 메타 정보: 평점(★ N.N), 거리(km), 등록일
- 메모(있을 경우만, 말줄임 처리)
- **공개 범위 배지** — 작성자 본인의 기록에만 표시 ("나만 보기" / "그룹 공유" / "전체 공개")
- **작성자 정보** — "공유받은 기록"·"둘러보기" 탭에서만 표시 (이름 + 프로필 사진)
- "지도" 버튼 — 지도 모달 또는 새 창 (§5.7)

- 카드 클릭 시 `/records/:recordId` 로 이동한다.
- 페이지네이션: 페이지당 10건, 이전/숫자/다음. 전체 1페이지 이하면 숨긴다.
- 등록 FAB: "+ 등록" 플로팅 버튼. 비로그인 클릭 시 로그인 화면으로 유도한다.

## 5. 기능 요구사항

### 5.1 기록 등록 (`/records/register`)
- 등록은 모달이 아닌 **별도 URL 페이지**에서 수행한다. 뒤로가기/취소 시 목록으로 복귀한다.
- 비로그인 상태로 직접 접근하면 로그인 화면으로 리다이렉트한다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 장소명 | 필수 | **직접 입력 불가(읽기 전용 input)**. §5.2 장소 검색 모달에서 선택해야 채워진다 |
| 카테고리 | 필수 | 관광지 / 쇼핑 / 맛집 단일 선택 |
| 위치 | 필수 | 검색 모달에서 장소명과 함께 자동으로 채워진다 (지도 직접 클릭은 미지원) |
| 평점 | 필수 | 0.5~5.0, **0.5 단위**. 별 하나의 좌/우 절반을 눌러 반 개 단위로 선택 |
| 사진 | 선택 | 다중 첨부. 업로드 전 미리보기 제공 (§8 제한) |
| 메모 | 선택 | 기록에 대한 자유 설명, 1000자 이하 |
| 공개 범위 | 필수 | **기본 선택은 "나만 보기"** (§5.5) |
| 태그 | — | 백엔드는 지원하지만 현재 입력 UI 없음 (§10) |

- 장소명 input은 비활성 상태로 표시되고 옆에 "검색" 버튼을 둔다. 버튼 클릭 시에만 검색 모달이 열린다.
- 검색 모달에서 선택하면 장소명 외에 주소·도로명주소·좌표·**원본 링크**가 폼 상태에 채워지며,
  화면에 노출되지 않더라도 등록 요청에 함께 전송된다 (공통 명세 §6.6).
- 입력값 검증 실패 시 인라인 오류를 표시한다. 장소 미선택 제출은 "장소를 검색해 선택해주세요",
  평점 미입력은 "평점을 선택해주세요"로 안내한다.
- **등록 버튼 한 번이 API 최대 2회 호출로 나뉜다** — `POST /api/records`(장소·카테고리·위치·평점·
  메모·공개 범위) → `POST /api/records/{id}/photos`(사진). 사진을 첨부하지 않으면 1회로 끝난다.
  1이 성공하고 2가 실패하면 **사진이 빠진 기록이 남으므로**, 상세 화면으로 이동시킨 뒤
  "사진 업로드에 실패했습니다. 다시 시도해주세요"로 안내하고 재업로드 동선을 제공한다.
  기록 자체는 유효하므로 되돌리지 않는다.
- 등록 성공 시 "내 기록" 탭으로 이동하고, 정렬이 "최근 등록순"일 때 새 항목이 최상단에 보인다.
- 등록 실패(네트워크·인증 만료) 시 오류를 안내하고 입력값(선택된 장소 포함)은 유지한다.

### 5.2 장소 검색 모달
등록 폼의 "검색" 버튼으로 열리는, 우편번호 검색창과 유사한 모달이다.

- 상단에 검색어 입력창과 "검색" 버튼. 결과 목록은 아래에 표시된다.
- 결과는 **10건씩 페이지네이션**하고, **기준 위치(§5.3)로부터 가까운 거리순**으로 정렬한다.
- 각 항목에는 최소 장소명·주소를 표시한다. 클릭 시 장소명·위치(주소·도로명주소·좌표)·원본 링크를
  폼에 전달하고 모달을 닫는다.
- 결과가 없으면 빈 상태 문구를 표시한다.
- **"장소 ID"는 존재하지 않는다.** 네이버 지역 검색이 고유 식별자를 제공하지 않아 백엔드 설계에서
  기각되었으므로, 프론트엔드도 `placeId` 를 보관·전송하지 않는다 (공통 명세 §3.5, §4.2).
- 백엔드가 집계·정렬·페이지네이션한 결과를 그대로 받아 표시한다. 원본 API의 5건 상한 때문에
  결과가 10건에 못 미칠 수 있으며, 이는 정상 동작이다.
- 검색 API는 브라우저에서 직접 호출하지 않는다 (CORS 미지원·키 노출). 반드시 백엔드를 경유한다.

### 5.3 기준 위치(현재 위치) 처리
거리순 정렬과 장소 검색 정렬의 기준이 되는 위치를 다음 우선순위로 결정한다.

1. **브라우저 Geolocation API** (`navigator.geolocation.getCurrentPosition()`). HTTPS 또는
   localhost에서만 동작하며 오리진마다 사용자의 명시적 허용이 필요하다. 거부·미지원은 실패로 처리한다.
2. 사용할 수 없거나 사용자가 원치 않으면 **직접 지정**할 수 있는 UI를 제공한다 (지도 클릭 또는
   장소 검색). 지정한 위치는 **브라우저 로컬 저장소에만** 보관한다.
3. 둘 다 없으면 **기본 위치는 서울역**(위도 37.5546, 경도 126.9706).

**위치정보법 원칙** (공통 명세 §5): Geolocation 좌표는 클라이언트에서만 일시적으로 사용하고,
사용자 식별자와 연결해 서버에 저장·전송하지 않는다. 거리 계산을 위해 서버로 보내는 `lat`/`lng` 는
요청 파라미터로만 쓰인다.

### 5.4 기록 상세 (`/records/:recordId`)
- 카드 클릭 시 **별도 라우트**로 이동한다. 상세 URL 공유·새로고침·뒤로가기가 동작해야 한다.
- 표시 항목:
  - 장소명, 카테고리, 위치(주소), 작성자(이름·프로필 사진), 등록일 (수정되었으면 "수정됨")
  - 사진 갤러리
  - **평점(★ N.N)과 메모** — 작성자 본인의 기록이면 인라인 수정 가능
  - 지도 보기 (§5.7)
- **작성자 본인에게만** 추가로 노출되는 것:
  - 공개 범위 설정 UI (§5.5)
  - 수정·삭제 버튼, 사진 추가·삭제
- 열람 권한이 없는 기록(또는 없는 기록)에 접근하면 서버가 `404` 를 주므로, 화면은 "존재하지 않거나
  볼 수 없는 기록입니다" 하나의 문구로 안내한다. **권한 부족과 부재를 구분해 표시하지 않는다** —
  구분하면 비공개 기록의 존재가 드러난다.
- 삭제는 되돌릴 수 없는 동작이므로 확인 단계를 거친다. 브라우저 기본 `confirm()` 대신 모달을 사용한다.

### 5.5 공개 범위 설정
등록 폼과 상세 화면에서 동일한 컴포넌트를 사용한다.

- 세 개의 선택지를 라디오 형태로 제시한다.

| 선택지 | 보조 설명 |
|---|---|
| 나만 보기 | "나만 볼 수 있습니다" |
| 그룹 공유 | "선택한 그룹의 멤버가 볼 수 있습니다" |
| 전체 공개 | "링크를 아는 누구나, 로그인하지 않아도 볼 수 있습니다" |

- **기본 선택은 항상 "나만 보기"** 다. 사용자가 명시적으로 넓히지 않는 한 공개되지 않는다.
- "그룹 공유"를 선택하면 그 아래에 **내 그룹 목록이 다중 선택 체크박스로 펼쳐진다.**
  여러 그룹을 동시에 선택할 수 있다.
- 그룹이 하나도 없는 사용자가 "그룹 공유"를 선택하면 목록 대신 "아직 공유 그룹이 없습니다"와
  그룹 만들기(`/groups`) 링크를 보여준다.
- **"그룹 공유"인데 선택된 그룹이 0개면 경고를 표시한다** — "선택한 그룹이 없어 나만 볼 수 있습니다".
  저장은 막지 않는다 (공통 명세 §3.2).
- 상세 화면에서 범위를 바꾸면 즉시 저장되고(`PATCH`), 결과를 토스트 등으로 알린다.
  범위를 좁히는 변경은 "이제 ○○님만 볼 수 있습니다"처럼 결과를 분명히 알린다.

### 5.6 그룹 관리
#### 5.6.1 그룹 목록 (`/groups`)
- 내가 소유한 그룹과 멤버로 속한 그룹을 함께 보여주고, 각 항목에 **소유자/멤버 역할 배지**와
  멤버 수(`N/5`)를 표시한다.
- "그룹 만들기" 버튼 — 이름(30자 이하)만 입력받아 생성한다.
- 빈 상태: "공유 그룹을 만들면 특정 기록을 원하는 사람에게만 보여줄 수 있습니다."

#### 5.6.2 그룹 상세 (`/groups/:groupId`)
- 멤버 목록(이름·프로필 사진·참여일)과 `N/5` 정원 표시.
- **소유자에게만**: 초대 링크 발급/재발급, 멤버 제외, 그룹 이름 변경, 그룹 삭제.
- **멤버에게만**: 탈퇴 버튼. 소유자는 탈퇴할 수 없고 삭제만 가능하다.
- 그룹 삭제 시 확인 모달에서 결과를 명시한다 — "이 그룹으로만 공유한 기록은 나만 보기 상태가
  됩니다. 기록 자체는 삭제되지 않습니다."
- 멤버 제외·탈퇴도 즉시 열람 권한이 사라지므로 확인 단계를 둔다.

#### 5.6.3 초대 링크
- 소유자가 "초대 링크 만들기"를 누르면 토큰을 받아 `/invites/:token` 전체 URL을 만들어
  **복사 버튼과 함께** 표시하고, **만료 시각(발급 후 7일)을 함께 안내한다.**
- **재발급 시 이전 링크가 즉시 무효**가 되므로, 재발급 버튼에 이 사실을 명시한다 —
  "새 링크를 만들면 이전 링크는 사용할 수 없습니다."
- 정원이 찬 그룹에서는 초대 링크 발급 UI를 비활성화하고 사유를 표시한다.
- 링크 폐기 버튼을 함께 제공한다.

#### 5.6.4 초대 수락 (`/invites/:token`)
- 비로그인으로도 열 수 있다. 그룹명·초대자 이름·만료 시각을 보여주고,
  비로그인이면 "로그인하고 참여하기", 로그인 상태면 "참여하기" 버튼을 표시한다.
- 로그인 후 원래의 초대 페이지로 되돌아와야 한다 (리다이렉트 경로 보존).
- 상태별 안내:
  - 만료(`410 INVITE_EXPIRED`): "초대 링크가 만료되었습니다. 초대한 분께 새 링크를 요청해주세요."
  - 없음(`404 INVITE_NOT_FOUND`): "유효하지 않은 초대 링크입니다."
  - 정원 초과(`409`): "그룹 정원(5명)이 가득 찼습니다."
  - 이미 멤버: 오류가 아니다. 그대로 그룹 상세로 이동시킨다.
- 수락 성공 시 그룹 상세로 이동하고, "공유받은 기록" 탭에서 확인할 수 있음을 안내한다.

### 5.7 지도 연동 (네이버 지도)
- 위치는 **네이버 지도(NAVER Maps) JavaScript SDK v3**로 표시한다.
- 네이버 지도는 단순 임베드 URL(`<iframe src=...>`)을 제공하지 않으므로, NCP Client ID로 SDK
  스크립트(`https://oapi.map.naver.com/openapi/v3/maps.js?ncpClientId=...`)를 로드하고
  `naver.maps.Map` 인스턴스를 컨테이너에 렌더링한다.
- "지도" 버튼 클릭 시:
  - Client ID가 설정된 경우: 모달 내 지도에 마커를 표시한다.
  - Client ID가 없는 경우: 새 창으로 네이버 지도 검색 결과(`https://map.naver.com/p/search/...`)를 연다.
- 지도 모달은 오버레이 클릭 또는 닫기(X)로 닫히며, 하단에 "새 창에서 네이버 지도로 열기" 링크를 둔다.
- 설정 메뉴에서 표시 방식(SDK 임베드/새 창)을 선택할 수 있다.
- 주소↔좌표 변환은 네이버 지도 API v3의 Geocoder 서브모듈을 사용한다.
- 환경변수는 `VITE_NAVER_MAP_CLIENT_ID` 를 사용한다.

## 6. 테마 (라이트 / 다크)

- 헤더의 테마 토글은 단일 토글(해/달 아이콘)로 라이트 ↔ 다크를 즉시 전환한다.
- 별도 선택이 없으면 시스템 설정(`prefers-color-scheme`)을 기본값으로 쓰고, 사용자가 명시적으로
  선택하면 그 값을 우선한다. 선택한 테마는 로컬 저장소에 저장해 새로고침 후에도 유지한다.
- **전체 색조는 파스텔톤 연두색을 기본 브랜드 컬러로 사용한다.**
  - 라이트: 밝고 채도가 낮은 연두 파스텔을 액센트로, 배경은 화이트/아이보리 계열.
  - 다크: 어두운 배경(짙은 그레이/그린) 위에 같은 연두 파스텔을 채도·명도만 조정해 유지한다.
- 공개 범위 배지는 세 상태가 한눈에 구분되어야 한다. **색상만으로 구분하지 않고 아이콘과 텍스트를
  함께 쓴다** (자물쇠/사람들/지구본 + "나만 보기"/"그룹 공유"/"전체 공개").

## 8. 비기능 요구사항
- 반응형 레이아웃: 모바일(360px~)부터 데스크톱까지 대응.
- 로딩/에러 상태: 목록 조회, 등록, 사진 업로드, 지도 로딩, 초대 수락 각각에 로딩 인디케이터와
  에러 메시지를 제공한다.
- 접근성: 모달은 `role="dialog"`/`aria-modal` 패턴을 유지하고, 폼 입력에는 라벨을 제공한다.
  테마 토글에는 현재 모드를 나타내는 `aria-label`(예: "다크 모드로 전환")을 제공한다.
  공개 범위 라디오 그룹에는 `fieldset`/`legend` 를 사용한다.
- 인증 토큰 및 민감 정보는 안전하게 보관하고, 네이버 지도 Client ID는 환경변수
  (`VITE_NAVER_MAP_CLIENT_ID`)로 관리한다. **네이버 지역 검색·OAuth 키는 브라우저에 두지 않는다.**
- 기준 위치(Geolocation) 관련: §5.3 원칙에 따라 실시간 GPS 좌표를 사용자 식별자와 연결해 서버에
  저장·전송하지 않는다.
- 이미지 업로드는 클라이언트에서 용량/포맷을 검증한 후 전송한다. 기본 제한은
  **1장당 5MB, 한 번에 첨부하는 전체 합계 30MB, jpg·png·webp** 이며, 제한을 넘는 파일은 첨부
  목록에 추가하지 않고 사유를 인라인 오류로 표시한다. 제한값은 환경변수
  (`VITE_MAX_PHOTO_SIZE_MB`, `VITE_MAX_PHOTO_TOTAL_MB`)로 조정 가능하며 백엔드 제한과 같은 값을
  유지해야 한다. 클라이언트 검증은 편의용이고 최종 검증 책임은 백엔드에 있다.
- **파비콘**: 서비스 타이틀의 "by YONG(용)"과 연계해 **용(龍) 모양** 파비콘을 사용한다.
  `frontend/public/favicon.svg` 를 용 형상의 SVG로 두며, 파스텔 연두 색조와 어울리는 라인/실루엣
  스타일로 제작한다.

## 9. 공개 범위 관련 UI 원칙
공개 범위는 이 서비스에서 실수가 가장 치명적인 지점이므로 다음을 지킨다.

- **기본값은 언제나 "나만 보기"** 다. 폼을 열었을 때 이미 공개로 선택되어 있는 상태를 만들지 않는다.
- 현재 상태를 **추론하게 만들지 않는다.** 목록 카드와 상세 화면 모두에서 작성자에게는 현재
  공개 범위를 항상 명시적으로 표시한다.
- 범위를 **넓히는** 변경(나만 보기 → 그룹/전체)은 그 결과를 문장으로 확인시킨다.
- 범위를 **좁히는** 변경은 되돌릴 필요 없이 즉시 적용하되, 누가 더 이상 볼 수 없게 되는지 알린다.
- 열람자 화면에는 공개 범위·공유 그룹을 **표시하지 않는다.** 누구에게 공유되었는지는 작성자만 아는 정보다.
- 사진 URL은 공개 범위와 무관하게 접근 가능하다는 한계가 있으므로 (공통 명세 §6.8),
  "비공개 기록의 사진은 절대 노출되지 않는다"고 오해할 문구는 쓰지 않는다.

## 10. 제약사항 및 향후 과제
- **아직 백엔드 API를 호출하지 않는다.** 화면은 목업 데이터(`frontend/src/data/records.js`,
  `groups.js`)와 `RecordsContext` 의 클라이언트 상태로 동작한다. 공개 범위 판정도 컨텍스트에서
  서버와 같은 규칙으로 계산하지만, 실제 차단 책임은 서버에 있다. 연동 시 API 호출과 응답 매핑
  레이어를 추가하고, 로그인 상태(`IS_LOGGED_IN`·`CURRENT_USER` 목업)를 실제 세션으로 교체해야 한다.
- **태그 입력·필터 UI 미구현**: 백엔드는 태그를 지원하지만 등록 폼·목록 필터에 UI가 없어
  등록 요청이 항상 빈 태그 목록으로 나간다.
- **사진 업로드 부분 실패**(§5.1): 기록은 생성되고 사진만 실패하는 상태가 가능하므로 재업로드
  동선이 필요하다.
- **공동 편집은 범위 밖이다.** 그룹은 조회 전용이며, 멤버가 남의 기록을 수정하는 UI는 없다
  ([`../REFERENCE.md`](../REFERENCE.md) 미결 사항 참고).
- **공개 링크(토큰 URL) 열람은 지원하지 않는다.** 비공개 기록을 링크로 공유하는 동선은 없다.
- 네이버 로그인(OAuth), 네이버 지도(NCP Client ID), 네이버 지역 검색(오픈 API)은 각각 별도의
  애플리케이션 등록·키 발급이 선행되어야 한다.
- **장소 검색의 구조적 한계** (공통 명세 §4.2): 검색어당 5건 상한 때문에 "10건씩 페이징 + 거리순
  정렬"이 항상 채워지지 않을 수 있다. 결과가 적게 나오는 것을 오류로 표시하지 않는다.
- **위치정보법 리스크**: §5.3 원칙을 지키되 실제 신고 대상 해당 여부는 법률 자문으로 확인이 필요하다.
- (향후 고려) 기록 검색(키워드), 지도 위에 내 기록 전체를 뿌리는 뷰, 기록 즐겨찾기/스크랩은
  본 버전 범위 밖이며 후속 명세에서 다룬다.
