# 여행 지도 (travel-recorder) 프론트엔드 요구사항 명세서

## 1. 개요

### 1.1 이 문서의 범위
본 문서는 `frontend/` 가 **화면으로 무엇을 보여주고 어떻게 동작하는지**를 정의한다 —
라우트, 탭·폼·모달 동작, 화면 문구, 테마, 접근성, 클라이언트 검증.

**서비스가 무엇인지는 여기서 정의하지 않는다.** 도메인 개념과 규칙, 공개 범위 정책, 모듈 간
계약은 [`../SPECIFICATION.md`](../SPECIFICATION.md) 가 소유하며 **충돌 시 공통 명세가 우선한다.**
API 시그니처·응답 스키마·오류 코드는 [`backend/SPECIFICATION.md`](../backend/SPECIFICATION.md) 를
따른다. 본 문서는 그 규칙이 **화면에서 어떻게 드러나야 하는지**만 적는다.

기술 스택은 React + Vite이며 자세한 구성은 [README](./README.md)에 있다.

### 1.2 화면 표기
[공통 명세 §3](../SPECIFICATION.md) 의 도메인 용어를 화면에서는 다음과 같이 부른다.

| 개념 | 화면 표기 |
|---|---|
| Trip | "여행" (목록 제목은 "내 여행", "공유받은 여행") |
| TripRecord | "여행지" (여행 상세 안) / "기록" (여행을 가로지르는 목록) |
| visibility `PRIVATE` | "나만 보기" |
| visibility `GROUP` | "그룹 공유" |
| visibility `PUBLIC` | "전체 공개" |
| Group | "공유 그룹" |
| headcount | "인원" |
| budget | "예산" |
| rating | "평점" (별점 UI) |
| coverPhoto | "대표 사진" |

- **"공유 그룹"과 "인원"을 화면에서 절대 섞어 쓰지 않는다.** 인원은 함께 간 사람 수이고,
  공유 그룹은 **여행을** 보여줄 대상이다 (공통 명세 §3.6). 이 둘을 혼동하는 것이 여행 폼에서
  가장 흔한 오해다.
- **"여행"과 "여행지"도 섞어 쓰지 않는다.** 여행은 상위 단위, 여행지는 그 안의 장소 한 곳이다.

### 1.3 본 개정으로 바뀌는 화면
여행(Trip) 계층 도입에 따라 다음이 달라진다. 이전 판들의 변경 이력은
[공통 명세 §0](../SPECIFICATION.md) 과 [REFERENCE.md](../REFERENCE.md) 에 있다.

| 폐기 | 신설 |
|---|---|
| 기록 등록 폼의 **공개 범위 선택 UI** | 여행 목록 `/trips`, 여행 만들기 `/trips/new`, 여행 상세 `/trips/:tripId` |
| 기록 상세의 **공개 범위 설정 UI** (→ 여행 상세로 이동) | 기록 등록 폼의 **소속 여행 선택** 단계 |
| 기록 카드가 자기 공개 범위를 표시하던 방식 (→ 소속 여행의 범위) | 대표 사진 지정, 소속 여행 변경 동선 |
| **기록 목록 `/records`** 와 **카테고리 탭** (→ 여행 상세의 하위 기록 목록) | 범위 탭 한 줄로 나누는 여행 목록 |

## 2. 사용자 및 인증

누가 무엇을 할 수 있는지는 [공통 명세 §2.6](../SPECIFICATION.md) 이 정의한다.
여기서는 **그 권한이 화면에 어떻게 드러나는지**만 적는다.

### 2.1 로그인 동선

> **현재 로그인 화면은 임시 아이디/비밀번호 폼이다.** 네이버 로그인 버튼은 주석으로 남겨 두었고,
> 폼 제출은 백엔드의 임시 로그인 API 로 간다 (backend §2.1). 아래 네이버 관련 내용은 복구 대상
> 명세로 남겨 둔다 (§10.2).

- 헤더 우상단에 비로그인 시 "로그인" 링크를, 로그인 시 사용자 프로필(이름·프로필 사진)과
  로그아웃 메뉴를 배치한다.
- 로그인 버튼은 백엔드 `/oauth2/authorization/naver` 로 **전체 페이지 이동**한다 (모달·팝업이
  아니다). 실패 사유는 `?error=` 쿼리로 받아 안내한다.
- 로그인 상태는 새로고침 후에도 유지된다 (세션 쿠키). 세션 만료 시 안내 후 재로그인을 유도한다.
- 모든 API 요청은 `credentials: 'include'` 로 보내고, 쓰기 요청에는 `X-XSRF-TOKEN` 헤더를 붙인다
  (공통 명세 §6.1).
- **로그인이 필요한 화면에 비로그인으로 진입하면 로그인으로 유도하되, 돌아올 경로를 보존한다.**
  공유받은 여행 상세(`/trips/:tripId`) 링크를 타고 들어온 경우가 특히 중요하다 — 로그인 후
  목록으로 떨어뜨리면 사용자가 그 여행을 다시 찾아야 한다.

### 2.2 비로그인 화면
- 보이는 것은 **"둘러보기" 탭 하나**뿐이다. "내 여행"·"공유받은 여행" 탭은 렌더링하지 않는다 (§4.2).
- 장소 검색 모달은 열 수 있다. 등록으로 이어지는 버튼에서 로그인으로 유도한다.
- **초대는 비로그인으로 볼 수 없다.** 초대는 받은 사람의 계정에 쌓이므로 로그인 후
  `/invites` 에서 확인한다 (§5.8.4). 열 수 있는 초대 링크는 존재하지 않는다.

### 2.3 권한에 따른 UI 노출
- **편집 UI(수정·삭제·사진 추가)는 소유자에게만 노출한다.** 기록 응답의 `isAuthor`,
  여행 응답의 `isOwner` 로 판단한다. 두 값은 같은 사실을 가리킨다 — 기록의 작성자는 소속 여행의
  소유자다.
- **공개 범위 변경 UI는 여행 화면에만 둔다.** 기록 화면에는 범위를 바꾸는 수단이 없고,
  현재 적용되는 범위를 읽기 전용으로만 보여준다 (§5.6).
- 소유자에게만 보이는 값은 **공개 범위 · 공유 그룹 목록** 둘이다. 판단 기준은 공통 명세 §3.5의
  노출 표이며, 서버가 열람자 응답에서 아예 빼고 내려준다.
- **예산은 열람자에게도 보인다.** 여행을 볼 수 있으면 예산도 보이므로, 공개 범위를 넓히는
  화면에서 이 사실을 함께 알린다 (§5.7).
- **버튼 노출 제어는 편의 기능일 뿐 보안 경계가 아니다.** 실제 차단은 서버가 한다.

## 3. 화면 목록

| 화면 | 경로 | 설명 |
|---|---|---|
| 인덱스/랜딩 | `/` | 서비스 소개 히어로, "둘러보기"(`/trips?scope=public`)·"네이버로 시작하기"(`/login`) CTA |
| **여행 목록** | `/trips` | 범위 탭, 여행 카드 그리드, 페이지네이션, 여행 만들기 FAB (§4) |
| **여행 만들기** | `/trips/new` | 이름·기간·인원·예산·설명·공개 범위 입력 폼 (§5.1) |
| **여행 상세** | `/trips/:tripId` | 여행 정보, 하위 기록 목록, 대표 사진 지정, (소유자면) 공개 범위 설정·수정·삭제 (§5.2) |
| 기록 등록 | `/records/register?tripId=` | **소속 여행 선택** + 장소·카테고리·평점·사진·메모 입력 폼 (§5.3) |
| 기록 상세 | `/records/:recordId` | 상세 정보, 사진 갤러리, 평점·메모, 지도, 소속 여행 링크 (§5.6) |
| 그룹 목록 | `/groups` | 받은 초대 **알림 줄**, 내가 소유하거나 속한 그룹 목록, 그룹 생성 |
| **초대함** | `/invites/received`, `/invites/sent` | 받은/보낸 탭. 각 탭에 대기 중인 초대와 **지난 초대 이력** (§5.8.4) |
| 그룹 상세 | `/groups/:groupId` | 멤버 목록, 이메일로 초대 보내기·대기 초대 취소, 멤버 제외/탈퇴, 그룹 삭제 |
| 로그인 | `/login` | **임시** 아이디/비밀번호 폼. 네이버 버튼은 주석 보존 (§2.1), `?error=` 안내 |
| 404 | 그 외 | 홈/여행 목록 복귀 링크 |
| 장소 검색 모달 | - | 기록 등록 폼의 "검색" 버튼으로 진입 (§5.4) |
| 대표 사진 선택 모달 | - | 여행 상세의 "대표 사진 지정" 버튼으로 진입 (§5.2.2) |
| 지도 모달 | - | 카드·상세의 "지도" 버튼으로 진입 (§5.9) |
| 설정 메뉴 | - | 지도 표시 방식 설정 (테마는 헤더 토글로 분리) |

- **로그인 사용자의 기본 진입 화면은 여행 목록(`/trips`)** 이다. 여행이 기록의 상위 그룹이자
  공유의 단위이므로 여행에서 출발해 기록으로 내려가는 것이 주 동선이다.
- **초대는 `/invites` 한 화면에 모은다.** 이전 판은 받은 초대를 그룹 목록 상단에 두고 별도
  라우트를 두지 않았다. 그 결정을 뒤집는 이유는 **보낸 초대와 이력이 갈 곳이 없기 때문**이다 —
  보낸 초대는 그룹 상세마다 흩어져 있어 "내가 누구를 초대해 두었더라"에 답하려면 그룹을 하나씩
  열어야 하고, 끝난 초대(공통 명세 §3.7)는 어느 그룹 화면에도 속하지 않는다.
- 그 대신 **`/groups` 상단에는 "받은 초대 N건" 알림 줄 하나만** 둔다. 같은 목록을 두 화면이
  각자 그리면 한쪽만 갱신되는 상태가 생긴다. 대기 중인 초대가 있으면 헤더의 그룹 메뉴에도
  건수 배지를 붙여 알린다.
- **나를 초대할 수 있는 그룹 수에는 제한이 없고 이력은 지워지지 않으므로**, 초대함의 모든 목록은
  페이지 단위로 받아 온다 (백엔드 §4.1).
- **여행을 가로지르는 기록 목록은 두지 않는다.** 기록은 언제나 여행 아래에서 본다 — 목록이
  하나뿐이라 "지금 무엇을 보고 있는지"가 흔들리지 않는다. 카테고리 필터와 거리순 정렬도 함께
  없앴으며, 여행을 가로지르는 검색이 필요해지면 그때 별도 화면으로 다시 검토한다 (§10.4).
- `/records` 로 들어온 요청은 `/trips` 로 보낸다. 남아 있는 링크·북마크를 404 로 떨어뜨리지
  않기 위해서다.

## 4. 목록 화면

목록 화면은 **여행 목록(`/trips`) 하나뿐이다.** 기록은 여행 상세 안에서만 목록으로 본다 (§5.2.1).

### 4.1 헤더 (`app-header`)
- 좌측: 위치 핀 아이콘 + "여행 지도" 타이틀 + "by YONG" 서브 라벨.
- 우측(`header-actions`): 좌측부터
  1. 여행 목록 진입 (`/trips`) — 로그인 시에만 노출
  2. 그룹 관리 진입 (`/groups`) — 로그인 시에만 노출
  3. 설정 메뉴 (`SettingsMenu`) — 지도 표시 방식
  4. 테마 토글 — 라이트/다크 (§6)
  5. 로그인 링크 또는 프로필/로그아웃 메뉴

### 4.2 범위 탭
여행 목록 최상단에 **범위 탭**을 배치한다. 세 범위는 성격이 달라 **한 목록에 섞지 않으며**,
API의 `scope` 파라미터로 그대로 전달된다 (백엔드 §4.1).

**목록을 나누는 탭은 이 한 줄뿐이다.** 카테고리 탭은 존재하지 않으며, 카테고리는 기록 카드의
배지로만 드러난다 (§4.6).

| `scope` | 보여주는 것 | 탭 이름 | 비로그인 |
|---|---|---|---|
| `mine` | 내가 소유한 여행 (공개 범위 무관) | "내 여행" | 숨김 |
| `shared` | 내가 속한 그룹으로 공유된 **타인의** 여행 | "공유받은 여행" | 숨김 |
| `public` | 전체 공개된 여행 (내 것 포함) | "둘러보기" | **표시 (유일한 탭)** |

- `scope` 는 **권한을 넓히는 수단이 아니다.** 어떤 값으로 요청하든 서버는 볼 권한이 있는 것만
  돌려준다. 탭은 이미 볼 수 있는 것 중에서 고르는 수단일 뿐이다.
- **기록의 범위 판정도 소속 여행 기준**이다. 기록 자체에는 공개 범위가 없다 (공통 명세 §3.5).
- 로그인 사용자의 기본 탭은 **"내 것"** 이다. 비로그인은 "둘러보기"만 보이며 그것이 기본이다.
- 탭 변경 시 페이지는 1페이지로 초기화된다.
- 빈 상태 문구는 화면·탭마다 다르게 쓴다.

| 탭 | 문구 |
|---|---|
| 내 여행 | "아직 여행이 없습니다. 다녀온 여행을 만들어보세요." |
| 공유받은 여행 | "공유받은 여행이 없습니다. 그룹에 참여하면 여기에 표시됩니다." |
| 둘러보기 | "공개된 여행이 없습니다." |

### 4.3 여행 목록 (`/trips`)
- 툴바: 좌측에 총 건수("총 N개의 여행"), 우측에 정렬 셀렉트(최근 만든 순 / 여행 시작일 순).
  **거리순 정렬은 없다** — 여행은 좌표를 갖지 않는다.
- 범위·정렬·페이지는 쿼리 파라미터로 유지한다 (`?scope=&sort=&page=`).
- 페이지네이션: 페이지 크기는 백엔드가 정하고 요청에는 `page` 만 싣는다 (백엔드 §4.1).
  전체 1페이지 이하면 숨긴다.
- "+ 여행 만들기" FAB. 비로그인 클릭 시 로그인 화면으로 유도한다.

### 4.4 여행 카드
카드 1건은 다음을 포함한다.

- 썸네일 영역: **대표 사진**(`coverPhotoUrl`). 지정되지 않았으면 플레이스홀더를 보여준다.
  서버는 대체 이미지를 고르지 않으므로 무엇을 보여줄지는 화면이 정한다.
- 여행 이름
- 기간 — `2026.09.05 – 09.08 (3박 4일)` 형식. **박·일 수는 종료일 − 시작일로 계산해 표시한다.**
  같은 날이면 "당일치기"로 쓴다.
- 인원 — "4명". 열람자에게도 보인다.
- 기록 수 — "여행지 11곳". 0이면 "아직 등록된 여행지가 없습니다"로 쓴다.
- **공개 범위 배지** — 소유자 본인의 여행에만 표시 ("나만 보기" / "그룹 공유" / "전체 공개").
  남의 여행에 배지를 달면 "누구에게 공유했는지는 소유자만 안다"는 규칙이 깨진다 (공통 명세 §3.5)
- **등록자** — 모든 탭에서 표시한다. 내 여행이면 "나"로 쓴다. 소유자의 이름·프로필 사진은
  열람자에게도 공개되는 값이다 (공통 명세 §3.5)
- **여행 설명** — 있으면 **두 줄까지 보여주고 넘치면 말줄임(…)** 한다. 자르는 일은 CSS 가 하며
  자바스크립트로 문자열을 자르지 않는다 — 자르는 위치는 글자 폭에 따라 달라져야 한다
- **예산은 카드에 표시하지 않는다.** 여행 상세에서만 보여주며, 열람자에게도 보인다 (§2.3).

- 카드 클릭 시 `/trips/:tripId` 로 이동한다.

### 4.5 기록 카드
여행 상세의 하위 기록 목록(§5.2.1)에서 쓰는 카드다. 기록만 모아 보는 화면은 없다 (§3).

- 썸네일 영역: 첫 번째 사진, 없으면 카테고리 아이콘 + 카테고리 배지
- 장소명, 지역명
- 메타 정보: 평점(★ N.N), 거리(km), 등록일
- 메모(있을 경우만, 말줄임 처리)
- "지도" 버튼 — 지도 모달 또는 새 창 (§5.9)
- **공개 범위 배지를 달지 않는다.** 범위는 여행의 값이고 그 여행 화면 안에 이미 보이므로,
  카드마다 반복하면 기록이 자기 범위를 가진 것처럼 읽힌다.
- **소속 여행 이름도 쓰지 않는다.** 한 여행의 목록이라 전부 같은 값이다.

- 카드 클릭 시 `/records/:recordId` 로 이동한다.

## 5. 기능 요구사항

### 5.1 여행 만들기 (`/trips/new`)
- 별도 URL 페이지에서 수행한다. 뒤로가기/취소 시 여행 목록으로 복귀한다.
- 비로그인 상태로 직접 접근하면 로그인 화면으로 리다이렉트한다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 여행 이름 | 필수 | 50자 이하. 플레이스홀더로 예시를 보여준다 ("제주 3박 4일") |
| 시작일 | 필수 | 날짜 선택. 미래 날짜도 허용한다 |
| 종료일 | 필수 | 날짜 선택. **시작일보다 앞설 수 없다** |
| 인원 | 필수 | 1 이상의 정수. **기본값 1**. 숫자 입력 + 증감 버튼 |
| 예산 | 선택 | 0 이상의 정수, 원 단위. 천 단위 구분 기호를 표시한다 |
| 여행 설명 | 선택 | 자유 텍스트, 1000자 이하 |
| 공개 범위 | 필수 | **기본 선택은 "나만 보기"** (§5.7) |
| 대표 사진 | — | **이 폼에 없다.** 하위 기록의 사진 중에서 고르므로 기록이 생긴 뒤에야 지정할 수 있다 (§5.2.2) |

- 기간 입력 옆에 **계산된 박·일 수를 즉시 보여준다** ("3박 4일", 같은 날이면 "당일치기").
  사용자가 날짜를 잘못 골랐을 때 저장 전에 알아차리게 하기 위해서다.
- 종료일이 시작일보다 앞서면 인라인 오류를 표시한다 — "종료일은 시작일 이후여야 합니다".
- **인원 입력 옆에 안내 문구를 둔다** — "함께 간 사람 수입니다. 공유 대상과는 무관합니다."
  인원과 공유 그룹을 혼동하는 것이 이 화면에서 가장 흔한 오해다 (§1.2).
- 저장 성공 시 만들어진 여행 상세(`/trips/:tripId`)로 이동하고, 기록이 0건이므로
  "여행지를 추가해 보세요" 안내와 등록 버튼을 강조한다.

### 5.2 여행 상세 (`/trips/:tripId`)
- 표시 항목:
  - 여행 이름, 기간(+ 박·일 수), 인원, 기록 수
  - 예산 (값이 있을 때만. **열람자에게도 보인다**, §2.3)
  - 여행 설명
  - 대표 사진 (지정된 경우)
  - 소유자(이름·프로필 사진), 만든 날 (수정되었으면 "수정됨")
  - 하위 기록 목록 (§5.2.1)
- **소유자 본인에게만** 추가로 노출되는 것:
  - 공개 범위 설정 UI (§5.7)
  - 여행 정보 수정 폼 — 만들기와 **같은 폼**을 쓴다 (§5.1). **단 공개 범위는 이 폼에 없다** —
    바로 위 공개 범위 섹션이 그 역할을 하므로 같은 값을 두 곳에서 바꾸게 두지 않는다
  - 여행 삭제 버튼
  - 여행 정보 수정·삭제 버튼
  - "여행지 추가" 버튼 → `/records/register?tripId={id}`
  - 대표 사진 지정 (§5.2.2)
- 열람 권한이 없는 여행(또는 없는 여행)에 접근하면 서버가 `404` 를 주므로, 화면은 "존재하지
  않거나 볼 수 없는 여행입니다" 하나의 문구로 안내한다. **권한 부족과 부재를 구분해 표시하지
  않는다** — 구분하면 비공개 여행의 존재가 드러난다.
- **공개 범위 설정과 여행 정보 수정은 접을 수 있다.** 기본은 접힌 상태이며, 접혀 있어도
  공개 범위 요약 줄에는 **현재 배지와 공유 그룹 이름을 남긴다** — 지금 누구에게 보이는지는
  펼치지 않고도 알아야 한다. 접기는 `details`/`summary` 로 만들어 키보드·스크린리더 동작을
  기본으로 얻는다.
- **여행 정보 수정은 저장 전에 확인 모달을 거친다.** 공개 범위는 이 폼에 없으므로 바뀌지
  않는다는 점을 문구에 담는다.
- **여행 삭제는 소유자에게만 보인다.** 하위 기록을 함께 지운다. 확인 모달에서 이 사실과 건수를 명시한다 —
  "이 여행과 여행지 11곳의 기록이 함께 삭제됩니다. 되돌릴 수 없습니다."
  브라우저 기본 `confirm()` 대신 모달을 사용한다.

#### 5.2.1 하위 기록 목록
- 여행 상세 안에서 `GET /api/records?scope=...&tripId=...` 로 조회한다.
- 카드는 §4.5를 따른다. 공개 범위는 화면 상단에 여행의 것으로 한 번만 표시한다.
- 정렬은 등록순(오래된 순)을 기본으로 한다. 여행을 따라가며 읽는 화면이기 때문이다.
- **기록 수에 제한이 없으므로** 서버 페이지네이션을 사용한다. 페이지 크기는 백엔드가 정하므로
  화면이 고르지 않으며(백엔드 §4.1), `page` 를 하나씩 올려 "더 보기"로 이어 붙인다.
- 기록이 0건이면 "아직 등록된 여행지가 없습니다"와 등록 버튼을 보여준다. 이는 오류가 아니다.

#### 5.2.2 대표 사진 지정
- 소유자에게만 보이는 "대표 사진 지정" 버튼으로 모달을 연다.
- 모달에는 **그 여행의 하위 기록에 올라온 사진 전부**를 격자로 보여주고, 하나를 골라 지정한다.
  "지정 해제" 버튼도 함께 둔다.
- 올라온 사진이 한 장도 없으면 버튼을 비활성화하고 사유를 표시한다 —
  "여행지에 사진을 먼저 올려주세요."
- 지정한 사진이 삭제되면 대표 사진 지정이 자동으로 해제된다 (공통 명세 §3.2). 화면은 다시
  플레이스홀더를 보여주며, 이를 오류로 표시하지 않는다.

### 5.3 기록 등록 (`/records/register`)
- 등록은 모달이 아닌 **별도 URL 페이지**에서 수행한다. 뒤로가기/취소 시 직전 화면으로 복귀한다.
- 비로그인 상태로 직접 접근하면 로그인 화면으로 리다이렉트한다.
- **진입 경로가 두 가지다.**
  - 여행 상세의 "여행지 추가" → `?tripId={id}` 로 들어오며 **소속 여행이 이미 정해져 있다.**
    여행 선택 UI 대신 "○○ 여행에 추가합니다"를 읽기 전용으로 표시한다.
  - 주소로 직접 들어온 경우 → `tripId` 없이 들어오며 **소속 여행을 먼저 골라야 한다.**
    내 여행이 하나도 없으면 "여행을 먼저 만들어 주세요"와 `/trips/new` 링크를 보여준다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 소속 여행 | 필수 | 내 여행 중에서 선택하거나 "새 여행 만들기". `?tripId=` 로 들어왔으면 읽기 전용 |
| 장소명 | 필수 | **직접 입력 불가(읽기 전용 input)**. §5.4 장소 검색 모달에서 선택해야 채워진다 |
| 카테고리 | 필수 | 관광지 / 쇼핑 / 맛집 단일 선택 |
| 위치 | 필수 | 검색 모달에서 장소명과 함께 자동으로 채워진다 (지도 직접 클릭은 미지원) |
| 평점 | 필수 | 0.5~5.0, **0.5 단위**. 별 하나의 좌/우 절반을 눌러 반 개 단위로 선택 |
| 사진 | 선택 | 다중 첨부. 업로드 전 미리보기 제공 (§8 제한) |
| 메모 | 선택 | 기록에 대한 자유 설명, 1000자 이하 |
| 공개 범위 | — | **이 폼에 없다.** 소속 여행의 값을 따른다 (§5.7) |
| 태그 | — | 백엔드는 지원하지만 현재 입력 UI 없음 (§10) |

- **소속 여행 선택**
  - 내가 소유한 여행만 후보로 내려온다. 최근 만든 순으로 보여주고 이름으로 검색할 수 있다.
  - 여행이 하나도 없으면 선택 목록 대신 "먼저 여행을 만들어 주세요"와 새 여행 만들기 폼을 연다.
  - "새 여행 만들기"를 고르면 §5.1과 같은 입력 항목을 **인라인 섹션으로 펼친다.** 별도 페이지로
    이동하면 입력하던 장소·평점이 날아가기 때문이다.
  - 선택한 여행의 **현재 공개 범위를 폼에 명시한다** — "이 기록은 ○○ 여행의 공개 범위(전체 공개)를
    따릅니다." 사용자가 공개 여부를 모른 채 저장하는 상황을 만들지 않기 위해서다 (§9).

- 장소명 input은 비활성 상태로 표시되고 옆에 "검색" 버튼을 둔다. 버튼 클릭 시에만 검색 모달이 열린다.
- 검색 모달에서 선택하면 장소명 외에 주소·도로명주소·좌표·**원본 링크**가 폼 상태에 채워지며,
  화면에 노출되지 않더라도 등록 요청에 함께 전송된다 (공통 명세 §6.4).
- 입력값 검증 실패 시 인라인 오류를 표시한다. 장소 미선택 제출은 "장소를 검색해 선택해주세요",
  평점 미입력은 "평점을 선택해주세요"로 안내한다.
- **등록 버튼 한 번이 API 최대 3회 호출로 나뉜다** (공통 명세 §6.2).

| 순서 | 호출 | 언제 |
|---|---|---|
| A | `POST /api/trips` | "새 여행 만들기"를 골랐을 때만 |
| 1 | `POST /api/records` (`tripId` 포함, **공개 범위 없음**) | 항상 |
| 2 | `POST /api/records/{id}/photos` | 사진을 첨부했을 때만 |

  - **A가 성공하고 1이 실패하면 기록이 0건인 여행이 남는다.** 이는 유효한 상태이므로 되돌리지
    않고, 만들어진 여행 상세로 이동시킨 뒤 "여행은 만들어졌습니다. 여행지 등록을 다시
    시도해주세요"로 안내한다. 재시도 시 여행은 이미 선택된 상태여야 한다.
  - **1이 성공하고 2가 실패하면 사진이 빠진 기록이 남으므로**, 기록 상세로 이동시킨 뒤
    "사진 업로드에 실패했습니다. 다시 시도해주세요"로 안내하고 재업로드 동선을 제공한다.
    기록 자체는 유효하므로 되돌리지 않는다.
- 등록 성공 시 **소속 여행 상세(`/trips/:tripId`)로 이동**한다. 방금 추가한 여행지가 목록에
  보여야 한다.
- 등록 실패(네트워크·인증 만료) 시 오류를 안내하고 입력값(선택된 여행·장소 포함)은 유지한다.

### 5.4 장소 검색 모달
등록 폼의 "검색" 버튼으로 열리는, 우편번호 검색창과 유사한 모달이다.

- 상단에 검색어 입력창과 "검색" 버튼. 결과 목록은 아래에 표시된다.
- 결과는 **5건씩 페이지네이션**하고(백엔드 §4.1), **기준 위치(§5.5)로부터 가까운 거리순**으로
  정렬한다.
- 각 항목에는 최소 장소명·주소를 표시한다. 클릭 시 장소명·위치(주소·도로명주소·좌표)·원본 링크를
  폼에 전달하고 모달을 닫는다.
- 결과가 없으면 빈 상태 문구를 표시한다.
- **"장소 ID"는 존재하지 않는다.** 네이버 지역 검색이 고유 식별자를 제공하지 않아 백엔드 설계에서
  기각되었으므로, 프론트엔드도 `placeId` 를 보관·전송하지 않는다 (공통 명세 §3.8, §4.2).
- 백엔드가 집계·정렬·페이지네이션한 결과를 그대로 받아 표시한다. 원본 API의 5건 상한 때문에
  결과가 한 페이지에 못 미칠 수 있으며, 이는 정상 동작이다.
- 검색 API는 브라우저에서 직접 호출하지 않는다 (CORS 미지원·키 노출). 반드시 백엔드를 경유한다.

### 5.5 기준 위치(현재 위치) 처리
거리순 정렬과 장소 검색 정렬의 기준이 되는 위치를 다음 우선순위로 결정한다.

1. **브라우저 Geolocation API** (`navigator.geolocation.getCurrentPosition()`). HTTPS 또는
   localhost에서만 동작하며 오리진마다 사용자의 명시적 허용이 필요하다. 거부·미지원은 실패로 처리한다.
2. 사용할 수 없거나 사용자가 원치 않으면 **직접 지정**할 수 있는 UI를 제공한다 (지도 클릭 또는
   장소 검색). 지정한 위치는 **브라우저 로컬 저장소에만** 보관한다.
3. 둘 다 없으면 **공통 명세 §5의 기본 위치**를 쓴다.

**위치정보법 원칙** (공통 명세 §5): Geolocation 좌표는 클라이언트에서만 일시적으로 사용하고,
사용자 식별자와 연결해 서버에 저장·전송하지 않는다. 거리 계산을 위해 서버로 보내는 `lat`/`lng` 는
요청 파라미터로만 쓰인다.

### 5.6 기록 상세 (`/records/:recordId`)
- 카드 클릭 시 **별도 라우트**로 이동한다. 상세 URL 공유·새로고침·뒤로가기가 동작해야 한다.
- 표시 항목:
  - 장소명, 카테고리, 위치(주소), 작성자(이름·프로필 사진), 등록일 (수정되었으면 "수정됨")
  - **소속 여행 이름** — 클릭하면 `/trips/:tripId` 로 이동한다. 상단 브레드크럼으로 둔다
  - 사진 갤러리
  - **평점(★ N.N)과 메모** — 작성자 본인의 기록이면 인라인 수정 가능
  - 지도 보기 (§5.9)
- **작성자 본인에게만** 추가로 노출되는 것:
  - 수정·삭제 버튼, 사진 추가·삭제
  - **소속 여행 변경** (§5.6.1)
- **공개 범위 설정 UI는 이 화면에 없다.** 공개 범위는 여행이 갖는다 (§5.7). 대신 현재 적용되는
  범위를 **읽기 전용 배지**로 보여주고, 그 옆에 "이 여행의 공개 범위" 설명과 여행 상세 링크를
  둔다. 작성자가 여기서 범위를 바꾸려 할 때 어디로 가야 하는지 막히지 않게 하기 위해서다.
- 열람 권한이 없는 기록(또는 없는 기록)에 접근하면 서버가 `404` 를 주므로, 화면은 "존재하지 않거나
  볼 수 없는 기록입니다" 하나의 문구로 안내한다. **권한 부족과 부재를 구분해 표시하지 않는다** —
  구분하면 비공개 기록의 존재가 드러난다. 소속 여행을 볼 수 없어 가려진 경우도 같은 문구다.
- 삭제는 되돌릴 수 없는 동작이므로 확인 단계를 거친다. 브라우저 기본 `confirm()` 대신 모달을 사용한다.
  **기록 하나를 지워도 여행은 남는다는 점**을 모달 문구에 담는다.

#### 5.6.1 소속 여행 변경
- 작성자에게만 보이는 "다른 여행으로 옮기기" 동작으로, 내 여행 목록에서 대상을 고른다.
- **옮기면 공개 범위가 대상 여행의 것으로 바뀐다.** 범위가 넓어지는 이동이면 확인 모달에서
  결과를 문장으로 확인시킨다 — "이 기록이 '전체 공개' 여행으로 옮겨집니다. 누구나 볼 수
  있게 됩니다." 좁아지는 이동은 확인 없이 진행하되 결과를 토스트로 알린다 (§9).
- 이 기록의 사진이 원래 여행의 대표 사진이었다면 그 지정이 해제된다는 것도 함께 안내한다.

### 5.7 공개 범위 설정 (여행 단위)
**여행 만들기 폼(§5.1)과 여행 상세(§5.2)에서만** 사용하는 컴포넌트다. 기록 화면에는 없다.

- 세 개의 선택지를 라디오 형태로 제시한다.

| 선택지 | 보조 설명 |
|---|---|
| 나만 보기 | "나만 볼 수 있습니다" |
| 그룹 공유 | "선택한 그룹의 멤버가 이 여행의 여행지를 모두 볼 수 있습니다" |
| 전체 공개 | "링크를 아는 누구나, 로그인하지 않아도 이 여행의 여행지를 모두 볼 수 있습니다" |

- **보조 설명에 "이 여행의 여행지를 모두"를 반드시 넣는다.** 여행 하나를 공유하면 하위 기록이
  전부 함께 보인다는 사실이 이 화면의 핵심이며, 빠뜨리면 사용자가 일부만 공유된다고 오해한다.

- **범위를 넓히는 선택지에는 예산도 함께 보인다는 사실을 덧붙인다** — "여행지와 예산을 모두 볼
  수 있습니다". 예산은 공개 범위를 그대로 따르므로(공통 명세 §3.5), 넓히는 순간 금액까지
  공개된다는 것을 저장 전에 알아야 한다.
- **기본 선택은 항상 "나만 보기"** 다. 사용자가 명시적으로 넓히지 않는 한 공개되지 않는다.
- "그룹 공유"를 선택하면 그 아래에 **내 그룹 목록이 다중 선택 체크박스로 펼쳐진다.**
  여러 그룹을 동시에 선택할 수 있다.
- 그룹이 하나도 없는 사용자가 "그룹 공유"를 선택하면 목록 대신 "아직 공유 그룹이 없습니다"와
  그룹 만들기(`/groups`) 링크를 보여준다.
- **"그룹 공유"인데 선택된 그룹이 0개면 경고를 표시한다** — "선택한 그룹이 없어 나만 볼 수 있습니다".
  저장은 막지 않는다 (공통 명세 §3.5).
- 여행 상세에서 범위를 바꾸면 즉시 저장되고(`PATCH /api/trips/{id}/visibility`), 결과를
  토스트 등으로 알린다. **몇 건의 기록이 영향을 받는지 함께 알린다** —
  넓힐 때 "여행지 11곳이 전체 공개됩니다", 좁힐 때 "여행지 11곳이 이제 나만 보기입니다".
- 범위를 넓히는 변경은 저장 전에 확인 모달을 한 번 거친다. 좁히는 변경은 확인 없이 즉시
  적용하되 결과를 알린다 (§9).

### 5.8 그룹 관리
#### 5.8.1 그룹 목록 (`/groups`)
- **받은 초대가 있으면 목록 위에 "받은 초대 N건" 알림 줄을 둔다** — 누르면 `/invites/received` 로 간다
  (§5.8.4). 초대가 없으면 줄 자체를 렌더링하지 않는다.
- 내가 소유한 그룹과 멤버로 속한 그룹을 함께 보여주고, 각 항목에 **소유자/멤버 역할 배지**와
  멤버 수(`N/5`)를 표시한다.
- "그룹 만들기" 버튼을 누르면 **생성 모달**이 열린다. 목록 화면에 입력칸을 늘어놓지 않고 모달로
  모으는 이유는, 이름에 메모가 더해지면서 한 줄 폼에 담기지 않기 때문이다.
  - **이름** — 필수. 비었으면 "그룹 이름을 입력해주세요.", 길이 초과는 "그룹 이름은 30자 이하로
    입력해주세요." (값 규칙은 공통 명세 §3.6)
  - **메모** — 선택. 여러 줄 입력이며 자리 표시는 "예: 설 연휴 사진 공유용". 비워 두어도 된다.
  - 오버레이 클릭 또는 "취소"로 닫는다. 닫으면 입력값은 버린다.
  - 만들면 모달이 닫히고 목록에 새 그룹이 나타난다. 화면 이동은 하지 않는다.
- 그룹 카드에는 메모가 있으면 이름 아래 한 줄로 함께 보여 준다. 넘치면 말줄임한다.
- 빈 상태: "공유 그룹을 만들면 특정 여행을 원하는 사람에게만 보여줄 수 있습니다."

#### 5.8.2 그룹 상세 (`/groups/:groupId`)
- 멤버 목록(이름·프로필 사진·참여일)과 `N/5` 정원 표시.
- **메모가 있으면 그룹 이름 아래에 보여 준다.** 소유자와 멤버 모두에게 보인다 (공통 명세 §3.6).
- **소유자에게만**: 초대 보내기와 대기 중인 초대 관리(§5.8.3), 멤버 제외, 그룹 이름·메모 변경,
  그룹 삭제.
- **멤버에게만**: 탈퇴 버튼. 소유자는 탈퇴할 수 없고 삭제만 가능하다.
- 그룹 삭제 시 확인 모달에서 결과를 명시한다 — "이 그룹으로만 공유한 여행은 나만 보기 상태가
  됩니다. 여행과 기록 자체는 삭제되지 않습니다."
- 멤버 제외·탈퇴도 즉시 열람 권한이 사라지므로 확인 단계를 둔다.
- 멤버가 아닌 그룹에 접근하면 `403` 이므로 "이 그룹의 멤버만 볼 수 있습니다" 로 안내하고, 없는
  그룹은 `404` 이므로 "존재하지 않는 그룹입니다" 로 안내한다. **여행·기록(§5.2, §5.6)과 달리 부재와
  권한 부족을 구분해 보여 준다** — 그룹은 존재를 숨기지 않기 때문이다 (backend §2.2.2).

#### 5.8.3 초대 보내기 (소유자)
- 이메일 입력 한 칸과 "초대 보내기" 버튼을 둔다. **자동완성이나 사용자 검색 결과를 붙이지
  않는다** — 가입자를 훑을 수 있는 화면을 만들지 않기 위해서다 (공통 명세 §3.7).
- 입력 옆에 안내를 둔다 — "상대가 이 서비스에 가입할 때 쓴 이메일을 정확히 입력해주세요."
- 그 아래 **대기 중인 초대 목록**을 이름·프로필 사진·보낸 시각으로 보여주고, 각 항목에
  **"초대 취소"** 를 둔다. 대기 중인 초대에는 이메일이 표시되지 않는다 (공통 명세 §3.7).
  도메인 용어는 "철회"지만(공통 명세 §3.7) 화면에서는 쓰지 않는다. 같은 화면의 모달에도
  "취소" 버튼이 있으므로 **"취소" 한 단어로 줄이지 않는다** — 무엇을 취소하는지가 드러나야 한다.
- 상태별 안내:
  - 가입자 없음(`404 USER_NOT_FOUND`): "해당 이메일로 가입한 사용자가 없습니다. 주소를 다시
    확인해주세요."
  - 이미 멤버(`409 ALREADY_MEMBER`): "이미 이 그룹의 멤버입니다."
  - 이미 초대함: 오류가 아니다. 기존 초대를 그대로 두고 "이미 초대한 상대입니다"로 알린다.
- **정원이 차도 초대 보내기를 막지 않는다.** 정원 판정은 수락 시점에 이루어지므로(공통 명세 §3.7)
  대신 **초대 폼 위에 정원 안내를 둔다** — "소유자를 포함해 최대 5명까지 참여할 수 있어요.
  지금 3/5명 · 대기 중인 초대 2건". 최대 인원을 숫자 비율로만 보여주면 "5" 가 무엇의 상한인지
  읽는 쪽이 짐작해야 한다.
- 정원이 찬 상태에서는 같은 줄에 결과를 덧붙인다 — "정원이 차서 지금은 수락되지 않아요. 자리가
  나면 같은 초대로 수락할 수 있어요." 보내는 것을 막지 않는 대신, 보내도 지금은 멤버가 되지
  못한다는 사실을 보내기 전에 알린다.
- **만료 안내 문구를 두지 않는다.** 초대는 수락·거절·취소, 그리고 그룹 삭제로만 끝나며 시간이
  지났다고 사라지지 않는다 (공통 명세 §3.7).
- 대기 중인 초대 목록은 페이지 단위로 받아 오고(백엔드 §4.1), 다음 페이지가 있으면 "더 보기"로
  이어 붙인다. 정원과 무관하게 초대를 보낼 수 있어 건수가 쌓일 수 있기 때문이다.

#### 5.8.4 초대함 (`/invites`)
로그인해야 보인다. **탭 두 개**로 나누고, 각 탭은 위에 **대기 중**, 아래에 **지난 초대**를 둔다.

| 탭 | 대기 중 | 지난 초대 (이력) |
|---|---|---|
| 받은 초대 | 그룹명 · 초대자 · 보낸 시각 · [수락] [거절] | 그룹명 · 초대자 · 끝난 시각 · 결과 |
| 보낸 초대 | 그룹명 · 상대 · 보낸 시각 · [초대 취소] | 그룹명 · 상대 · 끝난 시각 · 결과 |

- **탭은 경로로 나눈다** (`/invites/received`, `/invites/sent`). 두 탭은 같은 목록을 거른 것이
  아니라 담기는 항목과 동작이 다른 별개 목록이고, 조합될 다른 파라미터도 없다. 그룹 상세에
  다녀와도 보던 탭이 남는다. `/invites` 로 들어온 요청은 `/invites/received` 로 보내고, 그 밖의
  하위 경로는 404 다.
- **결과 표기는 네 가지**다 (공통 명세 §3.7) — "수락함/수락됨", "거절함/거절됨", "취소됨",
  "그룹이 삭제됨". 받은 쪽과 보낸 쪽은 같은 사실을 각자의 시점으로 읽으므로 **주어가 드러나는
  문구**를 쓴다. 보낸 탭의 거절도 감추지 않는다.
- **결과 배지는 색으로 성사 여부만 가른다.** 수락은 푸른색, 그 밖의 결과(거절·취소·그룹 삭제)는
  붉은색 테두리와 글자색이다. 끝난 방식마다 색을 따로 주지 않는다 — 문구가 이미 방식을 말하고
  있어 색을 늘려도 전달되는 것이 없다. 색은 배지에만 얹고 항목 전체를 칠하지 않는다. 결과 문구가
  그대로 남으므로 색만으로 구분되는 정보는 없다 (§6).
- **삭제된 그룹의 항목은 이름만 보여주고 링크를 걸지 않는다** (백엔드 §4.8의 `group.deleted`).
  취소선 같은 별도 표시를 이름에 얹지 않는다 — 삭제 사실은 "그룹이 삭제됨" 배지가 말한다.
- 지난 초대가 없으면 — "아직 끝난 초대가 없어요." 이력이 처음부터 비어 있는 것이 정상이며,
  **이력은 전환 시점부터 쌓인다**는 점을 안내로 설명하지 않는다 (사용자에게는 내부 사정이다).
- 대기 중인 초대 항목에 담기는 것은 **그룹명·상대·보낸 시각까지다.** 수락 전에는 멤버 목록도,
  그 그룹으로 공유된 여행도, **그룹 메모도** 보여주지 않는다 (공통 명세 §3.6, §3.7).
- **거절에는 확인 단계를 둔다** — "초대를 거절하면 지난 초대로 넘어가고, 거절한 사실이 보낸
  사람에게도 보입니다." 되돌릴 수 없고, 다시 참여하려면 상대가 새로 초대해야 한다.
  **거절이 상대에게 보인다는 사실을 거절 전에 알린다** (공통 명세 §3.7) — 누르고 난 뒤에 알게
  되면 되돌릴 방법이 없다.
- **"거절"은 붉은 바탕에 흰 글자로 둔다.** 되돌릴 수 없는 동작이라 확인 모달의 실행 버튼과 같은
  색을 쓴다. 되돌릴 수 있는 "초대 취소"·"멤버 제외"와는 다른 취급이며, 색만으로 구분하지 않도록
  확인 모달의 문구가 결과를 그대로 말한다.
- 상태별 안내:
  - 정원 초과(`409 GROUP_MEMBER_LIMIT_EXCEEDED`): "그룹 정원(5명)이 가득 찼습니다. 자리가 나면
    다시 수락할 수 있습니다." **초대는 목록에 그대로 남긴다.**
  - 사라진 초대(`404 INVITE_NOT_FOUND`): "이미 처리되었거나 취소된 초대입니다." 목록을 다시
    불러온다.
- 수락 성공 시 그 그룹 상세로 이동하고, "공유받은 여행" 탭에서 확인할 수 있음을 안내한다.
- **네 목록 모두 페이지 단위로 받아 온다**(백엔드 §4.1). 다음 페이지가 있으면 "더 보기"로
  이어 붙인다. 이력은 지워지지 않아 계정이 오래될수록 길어진다.

### 5.9 지도 연동 (네이버 지도)
- 위치는 **네이버 지도(NAVER Maps) JavaScript SDK v3**로 표시한다.
- 네이버 지도는 단순 임베드 URL(`<iframe src=...>`)을 제공하지 않으므로, NCP Client ID로 SDK
  스크립트(`https://oapi.map.naver.com/openapi/v3/maps.js?ncpClientId=...`)를 로드하고
  `naver.maps.Map` 인스턴스를 컨테이너에 렌더링한다.
- "지도" 버튼 클릭 시:
  - Client ID가 설정된 경우: 모달 내 지도에 마커를 표시한다.
  - Client ID가 없는 경우: 새 창으로 네이버 지도 검색 결과(`https://map.naver.com/p/search/...`)를 연다.
- 지도 모달은 오버레이 클릭 또는 닫기(X)로 닫히며, 하단에 "새 창에서 네이버 지도로 열기" 링크를 둔다.
- 설정 메뉴에서 표시 방식(SDK 임베드/새 창)을 선택할 수 있다.
- 주소↔좌표 변환은 네이버 지도 API v3의 Geocoder 서브모듈을 사용한다.
- 환경변수는 `VITE_NAVER_MAP_CLIENT_ID` 를 사용한다.

## 6. 테마 (라이트 / 다크)

- 헤더의 테마 토글은 단일 토글(해/달 아이콘)로 라이트 ↔ 다크를 즉시 전환한다.
- 별도 선택이 없으면 시스템 설정(`prefers-color-scheme`)을 기본값으로 쓰고, 사용자가 명시적으로
  선택하면 그 값을 우선한다. 선택한 테마는 로컬 저장소에 저장해 새로고침 후에도 유지한다.
- **전체 색조는 파스텔톤 연두색을 기본 브랜드 컬러로 사용한다.**
  - 라이트: 밝고 채도가 낮은 연두 파스텔을 액센트로, 배경은 화이트/아이보리 계열.
  - 다크: 어두운 배경(짙은 그레이/그린) 위에 같은 연두 파스텔을 채도·명도만 조정해 유지한다.
- 공개 범위 배지는 세 상태가 한눈에 구분되어야 한다. **색상만으로 구분하지 않고 아이콘과 텍스트를
  함께 쓴다** (자물쇠/사람들/지구본 + "나만 보기"/"그룹 공유"/"전체 공개").
- **성공·완료를 뜻하는 색은 초록이 아니라 파랑이다.** 브랜드 색이 연두라 초록으로 칠하면 액센트와
  섞여 구분되지 않는다 (§5.8.4의 결과 배지). 되돌릴 수 없는 동작을 뜻하는 붉은색과 마찬가지로
  라이트·다크가 같은 값을 쓴다.

## 7. 데이터 모델 (프론트엔드 관점)

백엔드 응답을 화면에서 다루는 **형태**만 보여 준다. 길이·범위·필수 여부 같은 **값 규칙은
공통 명세 §3이 유일한 출처**이며 주석에 중복해 적지 않는다. 필드 구성은
[backend §4](../backend/SPECIFICATION.md) 의 응답 예시와 1:1로 대응한다.

```
User {
  id: string
  name: string
  profileImageUrl: string
  // email 은 본인 정보(/api/auth/me) 외의 응답에 포함되지 않는다
}

Trip {
  id: string
  name: string
  startDate: string             // ISO date (YYYY-MM-DD)
  endDate: string               // ISO date
  headcount: number             // 함께 간 사람 수 (계정·공유 그룹과 무관)
  budget?: number               // 원 단위. 열람 권한이 있으면 누구에게나 내려온다
  memo?: string                 // 여행 설명
  coverPhotoUrl?: string        // 대표 사진 URL. 미지정이면 없음 (서버가 대체하지 않는다)
  recordCount: number           // 하위 기록 수. 0 일 수 있다
  owner: User
  isOwner: boolean              // 요청자가 소유자인지
  visibility?: 'PRIVATE' | 'GROUP' | 'PUBLIC'   // isOwner 일 때만 내려옴
  sharedGroups?: Group[]                         // isOwner 이고 GROUP 일 때만
  createdAt: string
  updatedAt: string
}

TripRecord {
  id: string
  trip: { id: string, name: string }   // 소속 여행. 항상 존재한다
  name: string                  // 검색 모달 선택으로만 채워짐 (직접 입력 불가)
  category: 'SIGHT' | 'SHOPPING' | 'FOOD'
  tags: string[]                // 백엔드가 내려주지만 현재 입력·표시 UI 없음 (§10)
  address: string
  roadAddress?: string
  location: { lat: number, lng: number }
  externalLink?: string         // 지역 검색 결과의 원본 링크 (장소 ID 대체)
  rating: number                // 작성자 본인의 평점 (평균 아님)
  memo?: string
  photos: string[]              // 이미지 URL 목록
  author: User                  // trip.owner 와 항상 같다
  isAuthor: boolean             // 요청자가 작성자(= 소속 여행 소유자)인지
  distanceKm?: number           // 기준 위치 기준 계산값 (거리순 정렬용)
  createdAt: string             // ISO date
  updatedAt: string             // createdAt 과 다르면 "수정됨" 표시
  // visibility·sharedGroups 는 기록에 없다. 소속 여행(Trip)에서 읽는다
}

Group {                         // 공유 대상 목록. 여행의 headcount 와 무관한 개념이다
  id: string
  name: string
  memo?: string                 // 그룹 설명. 목록·상세 모두에 담긴다
  owner?: User
  members?: User[]              // 그룹 상세에서만
  memberCount: number
  memberLimit: number           // 5
  isOwner: boolean
}

Invite {                        // 받은 초대 / 보낸 대기 초대. 이메일은 담기지 않는다
  id: string
  group?: { id: string, name: string }   // 받은 초대에만
  invitedBy?: User                        // 받은 초대에만
  invitee?: User                          // 소유자가 보는 대기 초대에만
  createdAt: string             // 보낸 시각. 만료 개념이 없다
}

InviteHistoryItem {             // 끝난 초대. 받은/보낸 어느 관점이든 모양이 같다
  id: string
  group: { id: string, name: string, deleted: boolean }  // name 은 끝난 시점의 스냅샷
  counterpart: User             // 관점에 따라 상대가 달라져 이름이 하나다 (backend §4.8)
  outcome: 'ACCEPTED' | 'REJECTED' | 'REVOKED' | 'GROUP_DELETED'
  invitedAt: string
  resolvedAt: string
}

// 장소 검색 모달의 결과 항목. 백엔드 GET /api/places/search 응답과 1:1 대응한다.
PlaceSearchResult {
  name: string
  category?: string             // 네이버 분류 문자열 (서비스 카테고리와 별개)
  address: string
  roadAddress?: string
  telephone?: string
  location: { lat: number, lng: number }
  distanceKm?: number           // 기준 위치가 있을 때만
  link?: string                 // 선택 시 externalLink 로 전달 (장소 ID 없음)
}
```

## 8. 비기능 요구사항
- 반응형 레이아웃: 모바일(360px~)부터 데스크톱까지 대응.
- 로딩/에러 상태: 목록 조회, 여행 생성, 기록 등록, 사진 업로드, 대표 사진 지정, 지도 로딩,
  초대 보내기·수락·거절 각각에 로딩 인디케이터와 에러 메시지를 제공한다.
- 접근성: 모달은 `role="dialog"`/`aria-modal` 패턴을 유지하고, 폼 입력에는 라벨을 제공한다.
  테마 토글에는 현재 모드를 나타내는 `aria-label`(예: "다크 모드로 전환")을 제공한다.
  공개 범위 라디오 그룹에는 `fieldset`/`legend` 를 사용한다. 여행 기간 입력은 시작일·종료일에
  각각 라벨을 주고, 계산된 박·일 수는 `aria-live="polite"` 로 읽히게 한다.
- 인증 토큰 및 민감 정보는 안전하게 보관하고, 네이버 지도 Client ID는 환경변수
  (`VITE_NAVER_MAP_CLIENT_ID`)로 관리한다. **네이버 지역 검색·OAuth 키는 브라우저에 두지 않는다.**
- 기준 위치(Geolocation) 관련: §5.5 원칙에 따라 실시간 GPS 좌표를 사용자 식별자와 연결해 서버에
  저장·전송하지 않는다.
- 이미지 업로드는 클라이언트에서 용량/포맷을 검증한 후 전송한다. **제한값은 공통 명세 §6.3이
  유일한 출처**이며, 프론트엔드는 환경변수(`VITE_MAX_PHOTO_SIZE_MB`, `VITE_MAX_PHOTO_TOTAL_MB`)로
  외부화해 백엔드와 같은 값을 유지한다. 제한을 넘는 파일은 **첨부 목록에 추가하지 않고** 사유를
  인라인 오류로 표시한다 — 올린 뒤 실패시키면 사용자가 무엇이 문제인지 늦게 안다.
  클라이언트 검증은 편의용이고 최종 검증 책임은 백엔드에 있다.
- **파비콘**: 서비스 타이틀의 "by YONG(용)"과 연계해 **용(龍) 모양** 파비콘을 사용한다.
  `frontend/public/favicon.svg` 를 용 형상의 SVG로 두며, 파스텔 연두 색조와 어울리는 라인/실루엣
  스타일로 제작한다.

## 9. 공개 범위 관련 UI 원칙
공개 범위는 이 서비스에서 실수가 가장 치명적인 지점이므로 다음을 지킨다.

- **공개 범위는 여행 하나에만 있다.** 기록 화면에 범위를 바꾸는 수단을 두지 않으며, 기록에
  표시되는 범위는 항상 "소속 여행의 것"임이 드러나야 한다 (§4.6, §5.6).
- **여행을 공유하면 하위 기록이 전부 함께 공개된다는 사실을 문구로 반복해 말한다** (§5.7).
  이 모델에서 가장 크게 놀랄 수 있는 지점이다.
- **기본값은 언제나 "나만 보기"** 다. 폼을 열었을 때 이미 공개로 선택되어 있는 상태를 만들지 않는다.
- 현재 상태를 **추론하게 만들지 않는다.** 목록 카드와 상세 화면 모두에서 작성자에게는 현재
  공개 범위를 항상 명시적으로 표시한다. **기록 등록 폼에서도 선택한 여행의 범위를 보여준다** (§5.3).
- 범위를 **넓히는** 변경(나만 보기 → 그룹/전체)은 그 결과를 문장으로 확인시킨다.
  **영향받는 기록 수를 함께 말한다.**
- 범위를 **좁히는** 변경은 되돌릴 필요 없이 즉시 적용하되, 누가 더 이상 볼 수 없게 되는지 알린다.
- **기록을 다른 여행으로 옮기는 것도 공개 범위 변경이다** (§5.6.1). 넓어지는 이동은 확인 모달을 거친다.
- 열람자 화면에는 공개 범위·공유 그룹을 **표시하지 않는다.** 누구에게 공유되었는지는 작성자만 아는 정보다.
- 사진 URL은 공개 범위와 무관하게 접근 가능하다는 한계가 있으므로 (공통 명세 §6.3),
  "비공개 여행의 사진은 절대 노출되지 않는다"고 오해할 문구는 쓰지 않는다.

## 10. 제약사항 및 향후 과제

도메인 차원의 미결 사항(공동 편집, 공개 링크, 방문일, 예산 범위 등)은
[공통 명세 §7](../SPECIFICATION.md) 에 있다. 여기서는 **프론트엔드가 해야 할 일**만 둔다.

### 10.1 여행(Trip) 계층에서 남은 것
라우트(`/trips`, `/trips/new`, `/trips/:tripId`)와 여행 카드·여행 폼, 소속 여행 선택, 기록
상세의 읽기 전용 범위 표시는 구현되어 있다. 남은 것은 다음과 같다.

- **대표 사진 지정이 없다** (§5.2.2). 사진 업로드 자체가 목업 단계라 고를 대상이 없다.
- **소속 여행 변경(다른 여행으로 옮기기)이 없다** (§5.6.1).
- **하위 기록 목록에 페이지네이션이 없다.** 지금은 전부 한 번에 그린다 (§5.2.1).

### 10.2 그 밖의 구현 잔여 작업
- **여행·기록·사진·태그가 아직 목업이다.** 인증(`AuthContext`)과 그룹·초대(`src/api/groups.js`,
  `GroupsContext`)는 실제 API 를 쓰지만, 여행·기록 화면은 `frontend/src/data/trips.js`·`records.js`
  와 `RecordsContext` 의 클라이언트 상태로 동작한다. 공개 범위 판정도 컨텍스트에서 서버와 같은
  규칙으로 계산하지만, **실제 차단 책임은 서버에 있다.**
- **목업 여행의 공유 그룹은 서버 그룹과 다른 id 체계다.** `MOCK_TRIPS.sharedGroupIds` 가
  `data/groups.js` 의 `MOCK_GROUPS` 를 가리키므로, 여행 화면의 `myGroups` 는 그룹 화면과 달리
  목업을 본다. 여행을 연동할 때 `data/groups.js` 와 `RecordsContext.myGroups` 를 함께 걷어낸다.
- **로그인 화면이 임시 아이디/비밀번호 폼이다** (§2.1). 네이버 버튼과 안내 문구는 주석으로 남아
  있으므로, 백엔드 OAuth 가 복구되면(backend §8.1) 주석을 풀고 임시 폼을 걷어낸다.
- **로그인이 필요한 화면에 라우트 가드가 없다** (§2.1). 비로그인 상태에서도 경로로 진입할 수는
  있으며, 소유자 전용 UI 만 사라진다. 돌아올 경로를 보존한 로그인 유도는 로그인 화면에서
  `state.from` 으로만 지원한다.
- **여행을 가로지르는 검색·거리순 정렬이 없다.** `/records` 목록을 없애면서 함께 사라졌다.
  "근처에 내가 가 본 맛집" 같은 동선이 필요해지면 별도 화면으로 다시 설계해야 한다 (§10.4).
- **태그 입력·필터 UI가 없다.** 백엔드는 태그를 지원하지만(backend §4.9) 등록 폼·목록 필터에
  UI가 없어 등록 요청이 항상 빈 태그 목록으로 나간다.
- **그룹 이름·메모 수정 UI가 없다** (§5.8.2). API 호출(`api/groups.js` 의 `updateGroup`)은
  준비되어 있지만 상세 화면에 진입점이 없어, 메모는 생성 시점에만 넣을 수 있다.
- **초대 수락 후 "공유받은 여행 탭에서 확인" 안내가 없다** (§5.8.4). 수락하면 그룹 상세로
  이동하지만 어디서 여행을 볼 수 있는지는 말하지 않는다.
- **사진 업로드 부분 실패 동선**(§5.3): 기록은 생성되고 사진만 실패하는 상태가 가능하므로
  재업로드 동선이 필요하다.

### 10.3 알려진 한계
- **장소 검색 결과가 요청 건수에 못 미칠 수 있다** (공통 명세 §4.2). 검색어당 5건 상한 때문이며,
  **결과가 적게 나오는 것을 오류로 표시하지 않는다.**
- **기록별 방문일이 없다** (공통 명세 §3.2). 여행 상세를 Day 1 / Day 2로 묶어 보여줄 수 없고,
  하위 기록은 등록순으로만 나열된다.
- **사진 URL은 공개 범위와 무관하게 접근 가능하다** (공통 명세 §6.3). §9의 문구 원칙을 지킨다.

### 10.4 이번 범위에 넣지 않은 화면
- **여행 상세의 지도 뷰** — 한 여행의 여행지를 지도에 한꺼번에 뿌리는 화면. 이 모델에서 가장
  자연스러운 확장이지만 이번 범위 밖이다.
- **여행 단위 요약** — 카테고리 분포, 여행 평점 요약, 동선. 여행 평균 평점은 의도적으로 만들지
  않는다 (공통 명세 §3.3).
- **기록 검색(키워드), 지도 위에 내 기록 전체를 뿌리는 뷰, 기록 즐겨찾기/스크랩** — 후속 명세에서 다룬다.

### 10.5 선행 조건
- 네이버 로그인(OAuth), 네이버 지도(NCP Client ID), 네이버 지역 검색(오픈 API)은 각각 **별도의
  애플리케이션 등록·키 발급**이 선행되어야 한다 (공통 명세 §4.1). 이 중 프론트엔드가 갖는 것은
  지도 Client ID 하나뿐이다.
- **위치정보법 해당 여부**는 §5.5 원칙을 지키되 법률 자문으로 확인이 필요하다 (공통 명세 §7.4).
